# Сценарии тестирования

## Этап 1 — основа проекта

### Автоматические тесты
1. На JDK 21 выполнить `mvn -B verify`. Ожидание: reactor завершает API и plugin модули успешно, JUnit 5 тесты зелёные.
2. Тесты YamlTextEditor проверяют сохранение комментариев при append, запрет дублирующего ID без учёта регистра, удаление одного блока и проверку ID.

### Ручные тесты на Purpur 1.20.6
1. Установить PrivateMobsX и собрать IronFrontiers. Ожидание: плагин включается и создаёт config.yml, messages.yml, sectors.yml, mobs.yml, blueprints.yml, menus.yml.
2. Подключить тестовую MySQL. Ожидание: HikariCP подключается; создаются таблицы if_schema и if_sector_state; лог сообщает количество загруженных состояний.
3. Повторить с остановленной БД/неверным портом. Ожидание: SEVERE, механики секторов не запускаются, плагин остаётся включённым в безопасном режиме, повторные подключения идут с экспоненциальной задержкой.
4. Изменить обычный параметр transform.tick_budget_ms и выполнить `/if reload`. Ожидание: новое значение перечитано без сообщения о рестарте.
5. Изменить database.host, multiserver.enabled или war_worlds и выполнить `/if reload`. Ожидание: активное значение не меняется, администратор получает отдельное сообщение для каждого изменённого пути.
6. Удалить один из softdepend. Ожидание: WARNING об отсутствующей интеграции; сам IronFrontiers не отключается.
7. При multiserver.enabled=false проверить, что поток IronFrontiers-Redis не создаётся.
8. Использовать `/if` без permission ironfrontiers.admin. Ожидание: сообщение об отсутствии прав из messages.yml.
9. Проверить MiniMessage и legacy ampersand-коды на тестовых сообщениях.
