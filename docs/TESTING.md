# Сценарии тестирования

## Этап 1 — основа проекта

### Автоматические тесты
1. На JDK 21 выполнить `mvn -B verify`. Ожидание: reactor завершает API и plugin modules успешно, JUnit 5 тесты зелёные. Последняя подтверждённая проверка feature-ветки: GitHub Actions run #5 для commit ee303fa — success.
2. YamlTextEditor: тесты проверяют сохранение комментариев при append, запрет дублирующего ID без учёта регистра, удаление одного блока и проверку ID.

### Ручные тесты на Purpur 1.20.6
1. Установить PrivateMobsX и собрать IronFrontiers. Ожидание: плагин включается и создаёт config.yml, messages.yml, sectors.yml, mobs.yml, blueprints.yml, menus.yml.
2. Подключить тестовую MySQL. Ожидание: HikariCP подключается; миграции создают if_schema и if_sector_state; лог сообщает количество загруженных состояний.
3. Повторить с остановленной БД/неверным портом. Ожидание: SEVERE, механики секторов не запускаются, плагин остаётся включённым в безопасном режиме, повторные подключения идут с экспоненциальной задержкой.
4. Отключить MySQL после успешного старта и вызвать несколько сохранений одного сектора. Ожидание: в памяти остаётся последнее состояние; старый in-flight snapshot не затирает более новый; после восстановления БД очередь очищается; WARNING не чаще одного раза в минуту.
5. Изменить transform.tick_budget_ms и выполнить `/if reload`. Ожидание: новое значение перечитано без сообщения о рестарте.
6. Изменить database.host, multiserver.enabled или war_worlds и выполнить `/if reload`. Ожидание: активное значение не меняется, администратор получает отдельное сообщение для каждого изменённого пути.
7. Удалить один из softdepend. Ожидание: WARNING об отсутствующей интеграции; сам IronFrontiers не отключается.
8. При multiserver.enabled=false проверить, что поток IronFrontiers-Redis не создаётся.
9. Использовать `/if` без permission ironfrontiers.admin. Ожидание: сообщение об отсутствии прав из messages.yml.
10. Проверить MiniMessage, legacy ampersand-коды и общий prefix на тестовых сообщениях.
